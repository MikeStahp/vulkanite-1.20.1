## 2024-05-19 - Removed Java Streams from Hot Paths & Fixed Semaphore Wait Logic
**Learning:** Hot rendering paths in Vulkanite (like `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, `CommandManager.Queue.waitForExecutions`) heavily penalize Java Streams due to per-frame garbage generation and autoboxing overhead. Furthermore, `.stream().max().orElse()` in timeline semaphore synchronization introduced a logical bug where a lesser incoming max value could overwrite a higher current wait value.
**Action:** When working on hot paths, especially those involving synchronization and rendering loops, replace Java Streams (`.mapToInt`, `.toList()`, etc.) with explicit `for` loops and array-based processing. Pre-allocate collections when sizes are known, and always ensure timeline semaphore operations are strictly monotonically increasing by carefully evaluating and storing only greater values.
