## 2024-05-19 - [Hot Path Stream Overhead & Command Timeline Bug]
**Learning:** Using Java Streams (like `stream().mapToInt()`, `stream().mapToLong().max()`) inside per-frame hot rendering loops (e.g., in `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, `CommandManager.Queue.waitForExecutions`) causes significant performance issues due to per-frame GC allocations and unboxing overhead. Furthermore, in `CommandManager.Queue.waitForExecutions`, the `.orElse()` fallback in a stream evaluation caused a logic bug where smaller incoming values could incorrectly decrease the overall `waitingFor` maximum wait timeline, violating strict monotonic increase.
**Action:** Always refactor Streams in per-frame rendering hot paths to standard `for` loops with explicit array sizes and pre-allocated `ArrayList`s using `.ensureCapacity()`. When calculating strictly increasing maximums for timeline semaphores, manually aggregate comparisons `Math.max(current, next)` instead of relying on Stream fallbacks.
