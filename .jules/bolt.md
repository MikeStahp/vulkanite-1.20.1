## 2024-06-25 - Avoiding Java Streams in Hot Rendering Paths
**Learning:** In Minecraft rendering contexts, code executes every frame (60+ times per second). Using Java Streams (`.stream().map()`, `.toList()`, `.toArray()`) within these hot paths causes massive overhead by creating new Stream, Iterator, and lambda objects per frame, leading to severe Garbage Collection (GC) spikes and performance stuttering. Additionally, stream-based mapping to primitive arrays (`.mapToInt().toArray()`) involves autoboxing overhead.
**Action:** When working in hot rendering paths (like `VulkanPipeline`, `VCmdBuff`, `CommandManager`, `MixinIrisRenderingPipeline`), always prefer traditional index-based or enhanced `for` loops with explicitly pre-allocated arrays (`new int[size]`) and collections (`new ArrayList<>(size)`). Avoid Streams entirely in these methods to eliminate GC pressure.
