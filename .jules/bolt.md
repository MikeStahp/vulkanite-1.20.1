## 2024-05-24 - [Java Streams in Hot Paths]
**Learning:** Using Java Streams (like `stream().mapToInt()`) in hot rendering paths (e.g., `VulkanPipeline`, `VCmdBuff`) causes significant per-frame GC allocations and unboxing overhead. Additionally, `stream().max().orElse()` in `CommandManager.Queue.waitForExecutions` had a logical bug where it could incorrectly decrease timeline semaphore wait values if incoming executions had a lower max than the current wait.
**Action:** Replace Java Streams with traditional indexed `for` loops (`for (int i = 0; i < list.size(); i++)`) and pre-allocated arrays in per-frame rendering code to maintain O(1) access without `Iterator` or stream allocations. Use `Arrays.fill` for constant value arrays. Ensure timeline semaphores always use monotonically increasing wait logic.
