## 2024-05-24 - Java Streams overhead in hot rendering loops
**Learning:** In hot rendering loops (like `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, `MixinIrisRenderingPipeline.getCustomTextures`), using Java Streams (`.stream().map().toList()`, `Arrays.stream()`) creates significant per-frame GC pressure and unboxing overhead. Additionally, using `.max().orElse()` over timeline semaphores introduces a subtle bug that incorrectly decreases wait values when the incoming maximum is smaller than the current timeline semaphore state.
**Action:** Replace Java Streams in hot paths with pre-allocated arrays and indexed loops (`for (int i = 0; i < size; i++)`). When generating constant-valued arrays, prefer `Arrays.fill()`. Ensure early returns in converted lambdas become `continue` statements. In `waitForExecutions`, implement strict monotonically increasing logic in a standard `for` loop to avoid regression bugs.
