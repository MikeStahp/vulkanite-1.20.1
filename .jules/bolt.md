## 2024-05-19 - EntityCapture Per-Frame Allocations
**Learning:** `EntityCapture.VertexCaptureProvider` runs per frame when capturing entities, meaning object allocations like `Map.compute` and `builderMap.forEach` create short-lived garbage every frame, causing GC pressure in hot paths. The `ClientWorld.getEntities()` loop is also executed per-frame, making it performance-critical. The `.forEach` and `.compute` methods create unnecessary lambda captures and iterator objects, which is a known anti-pattern in high-performance Java rendering loops.
**Action:** Avoid `.compute`, `.forEach`, and other lambda-based Java Stream operations in hot rendering paths. Prefer standard `for` loops, direct `Map.get`/`Map.put`, and reusable lists/arrays to minimize per-frame allocations.
