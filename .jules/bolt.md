
## 2024-05-24 - [Avoid Java Streams in LWJGL Hot Rendering Paths]
**Learning:** In Minecraft/LWJGL modding, rendering loops execute many times per second. Using Java Streams (like `stream().mapToInt()`) in these hot paths causes significant per-frame object allocation (boxing/unboxing and intermediate stream object creation), which leads to excessive Garbage Collection (GC) pressure and degraded framerates. Additionally, using Streams for maximum value calculation on monotonically increasing states (like timeline semaphores in `CommandManager.Queue.waitForExecutions`) can easily obscure bugs where new states decrease compared to old ones if the stream defaults back to a lower value instead of ensuring strict monotonicity.
**Action:** Always replace Java Streams in performance-critical rendering code with traditional `for` loops. Pre-allocate collections (`new ArrayList<>(size)`) or primitive arrays (`new int[size]`) based on the known size of the input to ensure $O(N)$ traversal with minimal allocation overhead.
