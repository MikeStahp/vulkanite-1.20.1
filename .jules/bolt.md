## 2024-05-18 - Replacing Streams with explicit loops
**Learning:** Found several hot code paths using Java Streams which cause unnecessary object creation and GC pressure per frame, especially primitive streams (e.g. `mapToInt`, `mapToLong`) or generating `List` elements through streams. `List.stream().map().toList()` and `.toArray()` cause unnecessary object allocation.
**Action:** Replace `Stream` chains in hot loops (like in `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, `CommandManager.waitForExecutions`, `MixinIrisRenderingPipeline.getCustomTextures`) with explicit `for` loops and array instantiations to reduce GC overhead. When calculating maximums over collections, standard loops over primitives or specific collections (without boxing to `Long`) should be used.
