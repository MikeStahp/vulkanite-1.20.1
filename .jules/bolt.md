## 2024-05-24 - Zero Allocation Render Loops in Vulkanite
**Learning:** In hot rendering paths like `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, and `CommandManager.Queue.waitForExecutions`, using Java Streams (`.stream().mapToInt()`, `stream().max().orElse()`) causes huge per-frame garbage generation (iterators, closures, boxing/unboxing). Also, `stream().max().orElse(current)` in a wait queue logic had a bug where an incoming max could be lower than the current waiting max, incorrectly decreasing the timeline wait value.
**Action:** Always refactor Streams to traditional loops in hot paths using basic arrays or pre-allocated collections. For `waitForExecutions`, ensure the new timeline value is strictly monotonically increasing using `Math.max(current, incoming_max)`.
