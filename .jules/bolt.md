## 2024-07-01 - Avoid Java Streams in hot rendering paths
**Learning:** In highly frequent methods like `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, `CommandManager.Queue.waitForExecutions`, and `MixinIrisRenderingPipeline.getCustomTextures` that execute every frame, using Java Streams (e.g. `.stream().mapToInt().toArray()`, `.stream().max()`, etc.) causes unnecessary per-frame object allocations (iterator, stream pipeline objects, boxing/unboxing overhead), increasing GC pressure and lowering framerate. Moreover, previous implementations involving `.max()` and `orElse()` had logic bugs where a new incoming execution stream might decrement a synchronization wait maximum.
**Action:** Always replace Java Streams in hot loops with explicit pre-sized collections/arrays and standard indexed `for (int i = 0; i < list.size(); i++)` loops. Add inline comments explicitly detailing *why* the optimization was chosen to satisfy code review requirements.
