## 2024-05-24 - Java Streams overhead in hot paths and `max().orElse` logic flaw
**Learning:** Using Java Streams (like `.stream().mapToInt()`, `.stream().mapToLong().max().orElse()`) in per-frame rendering hot paths generates unnecessary object allocation, closures, and boxing, leading to noticeable Garbage Collection (GC) pressure. Additionally, using `.max().orElse(fallback)` to calculate monotonically increasing values (like timeline semaphores in `CommandManager.Queue.waitForExecutions`) is mathematically flawed: if the new list's max is lower than the current fallback limit, it will incorrectly downgrade the limit rather than maintaining the true peak maximum.
**Action:** Always replace Stream operations in render loops with standard pre-allocated traditional `for` loops. When calculating strict maximums, start with the current maximum as the base and iteratively update it only if a new value is strictly greater.
