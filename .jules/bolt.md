## 2024-04-22 - Replacing Java Streams in Vulkan Hot Paths
**Learning:** In highly repetitive loops like Vulkan`s rendering pipeline (`VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`), using Java Streams (`.stream().map(...)`) creates significant GC pressure and per-frame object allocation due to boxing/unboxing and intermediate list creation. Even simple array mapping causes allocation overhead in hot paths.
**Action:** Always replace `.stream()` chains with traditional pre-allocated arrays and basic `for` loops in hot path routines. Additionally, be aware that replacing `mapToLong().max().orElse(...)` in `CommandManager.Queue.waitForExecutions` not only optimizes speed but also fixes a logical bug by ensuring timeline semaphore waits strictly monotonically increase.
