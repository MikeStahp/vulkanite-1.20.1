## 2024-05-18 - Eliminating Java Streams in Hot Rendering Paths
**Learning:** The Java Stream API introduces measurable object allocation overhead (lambdas, spliterators, stream pipeline objects) which creates high GC pressure when used inside per-frame rendering hot paths (like `VulkanPipeline.renderPostShadows`, `VCmdBuff.bindDSet`, etc.). Additionally, using stream `.max().orElse()` for tracking Vulkan timeline semaphore progression is dangerous because it can cause the expected execution maximum to decrease if an older list of execution IDs is provided.
**Action:** Replace all `.stream()` usages in hot paths with pre-sized loops (e.g. `new int[size]` and `new ArrayList<>(size)`) to achieve zero-allocation array copying and avoid timeline semaphore regressions by enforcing strict monotonic tracking (`if (execution > execMax)`).
