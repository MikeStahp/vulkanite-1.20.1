## 2024-05-18 - Eliminating Java Streams from Hot Paths
**Learning:** Java Streams (e.g., `.stream().mapToInt()`, `.stream().mapToLong().max().orElse()`) introduce significant per-frame overhead due to lambda allocations, primitive boxing/unboxing, and stream pipeline setup. In hot paths like the render loop (`VulkanPipeline.renderPostShadows`) and command buffering (`VCmdBuff.bindDSet`), this creates excessive Garbage Collection (GC) pressure. Additionally, operations like `.max().orElse(default)` can introduce logic bugs if the stream maximum is lower than the previous state but the `orElse` fallback only triggers on empty streams (violating monotonically increasing timeline requirements in `CommandManager.Queue.waitForExecutions`).
**Action:** Replace all stream usages in performance-critical methods with traditional `for` loops (or enhanced `for` loops where appropriate). This ensures $O(N)$ traversal with zero allocation and provides precise control over variable state updates (e.g., ensuring `execMax` only increases). Check for and refactor similar patterns in the future.
